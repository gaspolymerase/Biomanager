## BioManager 1.0.4

### New

- **What's new**, once after each update. The first page you open after BioManager is updated shows a short note: what is new, what works differently, and what was fixed, with a link to the full release notes.
  - **Got it** puts it away for good. **Help → What's new** opens it again.
  - If you skipped a version, you see the notes of each version since the last one you saw.
  - A new account sees the welcome tour instead.

### What works differently

- **Litter born** (it was *Litter born today*) asks for the date of birth before recording the litter.
  - The date starts as today; change it for a litter you found a day or two late.
  - A date in the future is refused.
  - If the cage already has a litter recorded, it says the new date replaces it.
- The colony, the admin *Colony overview* and printed cage cards say **Shared** for any shared cage, not only breeder cages.

### Fixed

- In an open cage, the header of the cage's mouse table no longer covers its first mouse.
- **Windows 10**: the desktop app no longer opens a blank or broken window on a PC without Microsoft Edge WebView2, the part of Windows its window uses.
  - It offers to download WebView2 from Microsoft and opens in your web browser meanwhile. Leave its message open while you use it.
  - Once WebView2 is installed, open BioManager again and it has its own window.
  - If the window can't open for another reason, it says why and opens in the browser too.
- On Windows, the window no longer fails to open because Windows marked the app's files as downloaded from the internet.

### Updating

- **Desktop app**: *Install and Restart* when it offers 1.0.4, or download it below. Your data is kept outside the app, and a copy is taken before the database is upgraded.
- **Lab server**:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.

  The database upgrades itself on start; every earlier release's database was checked to upgrade with nothing lost. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
